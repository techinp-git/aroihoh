# บันทึกรายการข้อมูลส่วนบุคคล (Data Map / RoPA ย่อ)

ปรับปรุง: 9 ก.ย. 2026 · อ้างอิงจากโค้ดจริง (schema.prisma + module ที่เกี่ยวข้อง) ไม่ใช่แม่แบบทั่วไป
ทุกครั้งที่เพิ่มฟิลด์ที่เป็นข้อมูลลูกค้า **ต้องอัปเดตไฟล์นี้และนโยบายความเป็นส่วนตัวด้วย**

## 1. เก็บอะไรบ้าง

| ข้อมูล | ที่เก็บ | ได้มาจาก | ใช้ทำอะไร | ฐานทางกฎหมาย (ที่ตั้งใจ) |
|---|---|---|---|---|
| LINE user ID | `customers.lineUserId` | LINE Login / webhook | ระบุตัวลูกค้า ส่งข้อความกลับ | จำเป็นเพื่อปฏิบัติตามสัญญา |
| ชื่อที่แสดง + รูปโปรไฟล์ | `customers.displayName`, `pictureUrl` | LINE Profile API | ให้ร้านรู้ว่าคุยกับใคร | จำเป็นเพื่อปฏิบัติตามสัญญา |
| เบอร์โทร | `customers.phoneEnc` (**เข้ารหัส AES-256-GCM**) | ลูกค้ากรอกเองในโปรไฟล์ (ไม่บังคับ) | ให้ไรเดอร์ติดต่อตอนส่ง | ความยินยอม (กรอกเอง = สมัครใจ) |
| ที่อยู่ + พิกัด + โน้ต | `addresses.detail/lat/lng/note` | ลูกค้าปักหมุด/พิมพ์เอง | คิดค่าส่ง เช็คเขต ส่งอาหาร | จำเป็นเพื่อปฏิบัติตามสัญญา |
| ประวัติการสั่ง | `orders`, `order_items` | ระบบบันทึกตอนสั่ง | ส่งอาหาร บัญชี รับประกันสิทธิ์ลูกค้า | สัญญา + หน้าที่ตามกฎหมาย (บัญชี/ภาษี) |
| ข้อความแชต | `chat_messages.text` | ลูกค้าทักผ่าน LINE OA | ตอบคำถาม แก้ปัญหาออเดอร์ | จำเป็นเพื่อปฏิบัติตามสัญญา |
| รูปที่ลูกค้าส่งในแชต | ไฟล์ใน volume `mediadata` + `chat_messages.imagePath` | ลูกค้าส่งรูป | ประกอบการแก้ปัญหา (เช่น อาหารผิด) | จำเป็นเพื่อปฏิบัติตามสัญญา |
| แท็กลูกค้า | `customers.tags` | ร้านติดเอง | จัดกลุ่มลูกค้า/ส่งข่าวสาร | ประโยชน์โดยชอบด้วยกฎหมาย ⚠️ ดูข้อ 4 |
| แต้มสะสม + ประวัติแต้ม | `customers.pointsBalance`, `loyalty_transactions` | ระบบบันทึกตอนสแกน/แลก | โปรแกรมสะสมแต้ม | จำเป็นเพื่อปฏิบัติตามสัญญา (โปรแกรมสมาชิก) |
| สถานะรับข่าวสาร | `customers.marketingOptedOut` | ลูกค้ากดเอง / พิมพ์ "หยุดข่าวสาร" / ร้านตั้ง | เคารพการปฏิเสธการตลาด | หน้าที่ตามกฎหมาย |
| หลักฐานความยินยอม | `customers.marketingConsentAt` + `marketingConsentSource` | ลูกค้ากดยอมรับ | พิสูจน์ได้ว่ายินยอมเมื่อไร มาจากไหน | หน้าที่ตามกฎหมาย (ม.19) |
| การรับทราบนโยบาย | `customers.policyAcceptedVersion` + `policyAcceptedAt` | ลูกค้ากด "รับทราบ" | พิสูจน์ว่าแจ้งแล้ว | หน้าที่ตามกฎหมาย |
| ประวัติการส่งข้อความ | `message_logs` | ระบบบันทึกตอนส่ง | กันส่งซ้ำ ตรวจสอบโควตา | ประโยชน์โดยชอบด้วยกฎหมาย |

**ไม่ได้เก็บ**: เลขบัตรประชาชน · ข้อมูลบัตรเครดิต (ยังเป็นเก็บเงินปลายทางอย่างเดียว) · ข้อมูลอ่อนไหวตามมาตรา 26 (ศาสนา สุขภาพ ฯลฯ)

## 2. ใครเห็นข้อมูลบ้าง

| ผู้รับ | เห็นอะไร | เหตุผล |
|---|---|---|
| เจ้าของร้าน / ผู้จัดการ | ทุกอย่างของแบรนด์ตัวเอง | ดำเนินกิจการ |
| พนักงาน (staff) | ออเดอร์ ลูกค้า แชต ของแบรนด์ที่ผูกไว้ | รับออเดอร์/ตอบแชต |
| ครัว (kitchen) | ออเดอร์ + ที่อยู่ · **ไม่เห็นเบอร์โทร** | ทำอาหาร/จ่ายงานไรเดอร์ |
| แชต (chat_agent) | แชต · **ไม่เห็นหน้าลูกค้า/รายงาน** | ตอบแชตอย่างเดียว |
| ไรเดอร์ | ชื่อที่แสดง ที่อยู่ พิกัด ยอดเก็บเงิน (บนใบปะหน้า) | ส่งอาหาร |
| LINE Corporation | ข้อความที่ส่ง/รับ ผ่าน LINE OA | เป็นช่องทางที่ลูกค้าเลือกใช้ |
| OpenStreetMap (Nominatim) | **คำค้นที่ลูกค้าพิมพ์ตอนหาที่อยู่** | ค้นหาสถานที่บนแผนที่ |

⚠️ ระบบบังคับ `assertBrandAccess` ทุก endpoint ที่รับ brandId → พนักงานแบรนด์หนึ่งเปิดข้อมูลอีกแบรนด์ไม่ได้ (มี e2e คุม)

## 3. เก็บไว้ที่ไหน นานแค่ไหน

| เรื่อง | สภาพจริงตอนนี้ |
|---|---|
| ที่ตั้งเซิร์ฟเวอร์ | Hetzner Cloud — **นอกประเทศไทย (สหภาพยุโรป)** ⚠️ ต้องแจ้งลูกค้าว่ามีการโอนข้อมูลข้ามประเทศ · ยืนยัน region จริงในคอนโซล Hetzner ก่อนประกาศ |
| ฐานข้อมูล | PostgreSQL ในเครื่องเดียวกัน · เบอร์โทรและ LINE credential เข้ารหัสด้วย `ENCRYPTION_KEY` |
| รูปแชต | Docker volume `mediadata` (ไม่ได้อยู่ใน DB) |
| สำรองข้อมูล | `scripts/backup.sh` ทุกวันตี 3 · **เก็บ 14 วัน** แล้วลบอัตโนมัติ |
| ระยะเวลาเก็บข้อมูลลูกค้า | ✅ **ลบอัตโนมัติแล้ว** — `dist/modules/pdpa/retention.cli.js` รันทุกวันตี 4 · บัญชี+ที่อยู่ 12 เดือนหลังใช้ครั้งสุดท้าย · แชต 12 เดือน · ออเดอร์ 5 ปี · ระยะเวลาอยู่ใน `src/modules/pdpa/retention.ts` **แก้ที่นั่นแล้วต้องแก้ในนโยบายด้วย** |
| การลบที่มีอยู่แล้ว | ที่อยู่ในสมุด = soft delete (`deletedAt`) · ที่อยู่บนออเดอร์เก่าเป็นสำเนาแยก ลบสมุดไม่กระทบ |

⚠️ **ลบข้อมูลแล้วยังค้างในไฟล์สำรองอีก 14 วัน** — ต้องเขียนไว้ในนโยบาย ไม่ใช่บอกลูกค้าว่า "ลบทันที"

## 4. ช่องว่างที่พบจากการอ่านโค้ด (ต้องตัดสินใจ)

1. ✅ **แก้แล้ว** — การตลาดขอความยินยอมก่อน (`canReceiveMarketing()`) · ลูกค้าเดิม backfill เป็น `legacy` ไม่ให้ reach ตก
2. ✅ **แก้แล้ว** — เก็บ `marketingConsentAt` + `marketingConsentSource` และ `policyAcceptedVersion` + `policyAcceptedAt`
3. ✅ **แก้แล้วบางส่วน** — มีปุ่มขอลบข้อมูลในหน้าโปรไฟล์ (เข้ากล่องแชตให้ร้าน) · **การลบยังทำมือ** ตาม `data-subject-requests.md` · ขอสำเนาข้อมูลยังต้องทักมาขอ
4. ✅ **แก้แล้ว** — มี job ลบตามระยะเวลาแล้ว (dry-run เป็นค่าเริ่มต้น ต้องใส่ `--apply` ถึงลบจริง)
5. ⚠️ **แต้มหมดอายุพร้อมบัญชี** — ลูกค้าที่เงียบเกิน 12 เดือนจะถูกลบและแต้มถูกตัดเป็น `expire` ใน ledger · เขียนไว้ในนโยบายแล้ว ควรบอกซ้ำในเงื่อนไขโปรแกรมสะสมแต้มด้วย
