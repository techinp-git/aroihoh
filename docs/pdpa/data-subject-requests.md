# รับมือคำขอใช้สิทธิของลูกค้า (ขอดู / ขอแก้ / ขอลบ)

ปรับปรุง: 9 ก.ย. 2026 · กฎหมายให้เวลาตอบ **30 วัน** นับจากได้รับคำขอ

## ก่อนทำทุกครั้ง

1. **ยืนยันตัวตนก่อน** — คำขอต้องมาจากบัญชี LINE ของเจ้าตัว (ทักผ่าน OA) หรืออีเมลที่ตรงกับที่เคยแจ้งไว้
   ห้ามส่งข้อมูลให้คนที่แค่ทักมาบอกว่าเป็นเจ้าของเบอร์นั้น
2. **บันทึกคำขอ** — วันที่ ใครขอ ขออะไร ทำอะไรไป ลงในสมุด/ชีตกลาง (ยังไม่มีระบบในแอป)

## 1. ขอดู / ขอสำเนาข้อมูล

ดูจากหน้าแอดมิน **ลูกค้า → เลือกลูกค้า** ได้เกือบทั้งหมด: ชื่อ แท็ก ที่อยู่ ประวัติออเดอร์ แต้มและประวัติแต้ม

สิ่งที่หน้าแอดมินไม่โชว์และต้องดึงจากฐานข้อมูล
```sql
-- ข้อความแชต
SELECT "createdAt", direction, text, "imagePath"
FROM chat_messages WHERE "customerId" = '<id>' ORDER BY "createdAt";

-- ประวัติการส่งข้อความหาลูกค้า
SELECT "createdAt", type, status FROM message_logs WHERE "customerId" = '<id>';
```
⚠️ **เบอร์โทรถูกเข้ารหัสอยู่** อ่านตรงจาก DB ไม่ออก — ให้ลูกค้าดูเองในหน้าโปรไฟล์ หรือถอดผ่านโค้ดที่มี `ENCRYPTION_KEY`

## 2. ขอแก้ไขข้อมูล

ลูกค้าแก้เองได้เลยในหน้าโปรไฟล์: ที่อยู่ทั้งหมด และเบอร์โทร
ชื่อที่แสดงกับรูปโปรไฟล์มาจาก LINE — แก้ที่ LINE แล้วระบบจะอัปเดตตามเมื่อทักมาครั้งถัดไป

## 3. ขอลบข้อมูล

✅ ลูกค้ากด **"ขอให้ลบข้อมูลของฉัน"** ในหน้าโปรไฟล์ได้แล้ว — คำขอจะโผล่ใน **กล่องแชต**
ของร้านเป็นข้อความขึ้นต้นด้วย `[คำขอลบข้อมูล]` (กดซ้ำในวันเดียวกันไม่แจ้งซ้ำ)

⚠️ **การลบยังต้องทำมือ** และต้องระวังว่า **ลบลูกค้าตรง ๆ ไม่ได้**
เพราะออเดอร์ ที่อยู่ และรายการแต้มอ้างถึงอยู่ (foreign key เป็น RESTRICT)

แนวทางที่แนะนำคือ **ลบข้อมูลระบุตัวตน แต่เก็บออเดอร์ไว้เป็นข้อมูลไม่ระบุตัวตน**
เพราะกฎหมายบัญชี/ภาษีให้เก็บหลักฐานการขายไว้ และ PDPA ไม่บังคับให้ลบสิ่งที่ต้องเก็บตามกฎหมายอื่น

```sql
BEGIN;
-- 1) ลบสิ่งที่ระบุตัวตนได้ออกจากบัญชีลูกค้า
UPDATE customers SET
  "displayName"      = 'ลบตามคำขอ',
  "pictureUrl"       = NULL,
  "phoneEnc"         = NULL,
  tags               = '{}',
  "marketingOptedOut"= true,          -- กันเผลอส่งข่าวสารหาอีก
  "lineUserId"       = 'deleted-' || id  -- ตัดการเชื่อมกับบัญชี LINE เดิม
WHERE id = '<id>';

-- 2) ข้อความแชตและรูป (ข้อความอาจมีชื่อ/เบอร์ที่ลูกค้าพิมพ์เอง)
DELETE FROM chat_messages WHERE "customerId" = '<id>';

-- 3) ที่อยู่ — เก็บเฉพาะที่ผูกกับออเดอร์ไว้เป็นหลักฐาน ที่เหลือลบ
DELETE FROM addresses a
WHERE a."customerId" = '<id>'
  AND NOT EXISTS (SELECT 1 FROM orders o WHERE o."addressId" = a.id);
UPDATE addresses SET detail = 'ลบตามคำขอ', note = NULL
WHERE "customerId" = '<id>';
COMMIT;
```

จากนั้น **ลบไฟล์รูปแชต** ใน volume `mediadata` ที่ตรงกับ `imagePath` ที่เพิ่งลบ

### ทดสอบแล้วว่าใช้ได้จริง (9 ก.ย. 2026)

รันชุดคำสั่งข้างบนกับลูกค้าทดสอบที่มีเบอร์โทร ที่อยู่ และข้อความแชตครบ ผลที่ได้
- ชื่อกลายเป็น "ลบตามคำขอ" · เบอร์โทรหาย · ปิดรับข่าวสารอัตโนมัติ · ตัดการเชื่อมกับบัญชี LINE เดิมแล้ว
- ข้อความแชตและที่อยู่ที่ไม่ผูกออเดอร์ถูกลบหมด
- **หน้าลูกค้าในแอดมินยังเปิดได้ปกติ (HTTP 200) ไม่พัง**
- **ลูกค้ากลับมาใช้บริการใหม่ได้** โดยได้บัญชีใหม่ที่ไม่ผูกกับข้อมูลเดิม
- คนที่ถูกลบไม่ถูกนับเป็นผู้รับ broadcast อีก

⚠️ ข้อควรระวังตอนรัน: ถ้าเข้า psql ผ่าน `docker exec` ต้องใส่ `-i` ด้วย
(`docker exec -i <container> psql ...`) ไม่งั้นคำสั่งจะไม่ถูกส่งเข้าไปและ **เงียบ ไม่มี error**
ทำให้เข้าใจผิดว่าลบแล้วทั้งที่ยังไม่ได้ลบ — ตรวจผลลัพธ์ทุกครั้งว่าขึ้น `UPDATE 1` / `DELETE n`

**ต้องแจ้งลูกค้าตามจริง**: ข้อมูลจะหายจากระบบทันที แต่สำเนาในไฟล์สำรองจะหายเองภายใน **14 วัน**
และประวัติการซื้อแบบไม่ระบุตัวตนยังถูกเก็บไว้ตามกฎหมายบัญชี

## 4. ขอถอนความยินยอมเรื่องข่าวสาร

**ไม่ต้องทำอะไรเพิ่ม** ลูกค้าถอนเองได้ 3 ทาง
1. ปิดสวิตช์ "รับข่าวสารและโปรโมชัน" ในหน้าโปรไฟล์
2. **พิมพ์ "หยุดข่าวสาร" ตอบกลับใน LINE** — ระบบถอนให้ทันทีและตอบยืนยัน
3. แอดมินตั้งให้จากหน้าลูกค้า

ระบบหักคนที่ถอนออกจากผู้รับทุกครั้ง และทุก broadcast มีวิธีปฏิเสธต่อท้ายอัตโนมัติ

## 5. ข้อมูลรั่วไหล

ถ้าสงสัยว่าข้อมูลรั่ว **ต้องแจ้ง สคส. ภายใน 72 ชั่วโมง** และแจ้งลูกค้าถ้าเสี่ยงสูงต่อสิทธิเสรีภาพ
ขั้นตอนแรกที่ทำได้ทันที: เปลี่ยน `ADMIN_JWT_SECRET`/`JWT_SECRET` เพื่อไล่ทุก session ออก
และหมุน `ENCRYPTION_KEY` ตามวิธีใน `docs/deploy-hetzner.md`

## สิ่งที่ควรทำเพิ่มในระบบ

- ปุ่ม "ขอลบบัญชีของฉัน" ในหน้าโปรไฟล์ที่ยิงเข้าคิวให้เจ้าของร้านกดยืนยัน — ตอนนี้ต้องรันคำสั่งเอง เสี่ยงพลาด
- ที่เก็บบันทึกคำขอใช้สิทธิในระบบ แทนที่จะจดนอกระบบ
